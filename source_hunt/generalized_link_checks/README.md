# Generalized archive-link test

Checked 27 October 2026 (New York date). The recovered pattern is:

```text
https://timesofindia.indiatimes.com/{YEAR}/{MONTH}/{DAY}/archivelist/year-{YEAR},month-{MONTH},starttime-{SERIAL}.cms
SERIAL = (requested_date - date(1899, 12, 30)).days
```

The year and month occur twice; both must change. `starttime` is a serial day number, not a Unix timestamp. The no-leading-date variant starts directly with `/archivelist/` and uses the same suffix.

Eight dates were tested with both URL forms: 2003-01-02, 2015-01-01, 2023-06-30, 2024-01-01, 2025-01-01, 2026-07-08, 2026-10-26 and 2026-10-27. **All 16 daily requests returned HTTP 200 and zero archive headline links**, with blank archive day headings. For each date, the two forms returned identical response hashes. This is missing archive content, not a zero-news day. Unrelated sidebar/footer headlines were excluded.

The January 2003 and October 2026 monthly calendar pages also loaded. Their day links are generated by JavaScript. In a JavaScript-enabled browser, the October calendar's actual rendered links for days 1 and 26 exactly matched the formula (serials 46296 and 46321). The generated October 27 daily page was also visibly empty in the browser. Thus the observed failure is not explained by merely leaving `starttime` unchanged, using the wrong date formula, omitting the leading date path, or failing to execute the calendar JavaScript. Its underlying cause is not established, and these tests do not prove all archive routes fail.
